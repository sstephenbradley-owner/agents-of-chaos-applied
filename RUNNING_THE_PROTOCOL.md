# What counts as running AoCA

There is no certification, no badge and no "AoCA-validated" label. Anyone can describe a run however they like. This note says what the author means by the name, so readers can tell a full run from a partial one.

## A run described as AoCA

1. **Two or more model families.** The Drafter and the Adversary come from different model families, not only different products or versions from the same developer. A run on one model is described as single-agent screening.
2. **Different context for the reviewer.** The Adversary does not get the Drafter's full working context. The three-chat setup (two informed sessions, one blind) is the v2.0 standard.
3. **The Accuracy Mandate is in the adversarial prompt**, verbatim or in substance: checkable citations for every finding, and unsupported findings logged rather than counted.
4. **An Independent Verification pass** checks the reviewer's citations before the human acts on them, in a fresh session.
5. **A human decides**, and the decision is recorded for every CRITICAL and HIGH finding: concede, dispute or flag, with a reason.
6. **A fabrication log is kept**, even when it is empty. Errors by any role count, including the verifier calling a real source fake.
7. **Disagreements are classified** and logged (v2.0, Section 5; in practice FACTUAL or EDITORIAL).

## Saying what you skipped

A run that leaves out any of the above should say which steps it skipped. "AoCA without Independent Verification" or "single-agent AoCA screening" is accurate. "Validated with AoCA" for a single-model run is not.

## What a run does not establish

A run shows that a document survived a structured adversarial review under stated conditions. It does not show that the document is correct. Reviewer scores are the reviewer's own and have no anchor definitions yet. Model families share errors (see Known limitations in the README), so agreement between them is weaker evidence than it looks.
